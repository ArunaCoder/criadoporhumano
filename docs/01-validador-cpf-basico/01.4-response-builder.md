### Passo 13.1: Cache de Arquivos Estáticos (Otimização Recomendada)

#### 💭 Pensamento do Engenheiro

**Contexto:**

Atualmente, quando servimos um arquivo estático (HTML, CSS, JS), fazemos:

1. Validar path (já em memória, rápido)
2. **Abrir arquivo no disco** (`fs::File::open()`) ← syscall bloqueante
3. **Ler conteúdo** (`fs::read()`) ← I/O de disco
4. Enviar ao cliente

Cada request repete passos 2-3, mesmo que seja o **mesmo arquivo**.

**O problema:**

I/O de disco é **1000-10.000x mais lento** que acesso à RAM:

```
RAM (L1 cache):     ~1 ns
RAM (main memory):  ~100 ns
SSD (NVMe):         ~100,000 ns (100 µs)
HDD:                ~10,000,000 ns (10 ms)
```

**Impacto real:**

- Servidor servindo `index.html` (5KB) 1000 vezes/segundo
- Sem cache: 1000 × 100µs = **100ms de CPU bloqueado em I/O**
- Com cache: 1000 × 0.1µs = **0.1ms total**
- **Ganho: 1000x redução em latência**

**Trade-off clássico: Memória vs I/O**

- ✅ **Cache:** Rápido, mas usa RAM
- ❌ **Sem cache:** Lento, mas zero RAM extra

**Decisão:** Para arquivos pequenos (<1MB) e acessados frequentemente (HTML/CSS/JS), cache compensa **sempre**.

**Estratégia: Lazy Loading + LRU**

1. **Lazy:** Só carregar arquivo no **primeiro** acesso (não pré-carregar tudo)
2. **LRU (Least Recently Used):** Se cache encher, remover arquivo menos usado

**Implementação:**

```rust
use std::sync::RwLock;
use std::collections::HashMap;
use std::path::PathBuf;

pub struct ServerConfig {
    pub base_canonical: PathBuf,
    pub file_cache: RwLock<HashMap<PathBuf, Vec<u8>>>,  // Thread-safe
}

fn serve_file(path: &Path, config: &ServerConfig) -> Result<Vec<u8>, String> {
    // 1. Tentar ler do cache (read lock - não bloqueia outros leitores)
    if let Some(cached) = config.file_cache.read().unwrap().get(path) {
        return Ok(cached.clone());  // Cache hit!
    }

    // 2. Cache miss: ler do disco
    let data = fs::read(path).map_err(|e| format!("File error: {}", e))?;

    // 3. Inserir no cache (write lock - exclusivo)
    config.file_cache.write().unwrap().insert(path.to_path_buf(), data.clone());

    Ok(data)
}
```

**Por que `RwLock`?**

- Múltiplas threads podem **ler** cache simultaneamente (comum: 99% das operações)
- Apenas **uma** thread pode **escrever** (raro: só no primeiro acesso)
- Mais eficiente que `Mutex` (que bloqueia leitura também)

**Proteções:**

1. **Limite de tamanho:** Não cachear arquivos >1MB
2. **Limite de cache total:** Máximo 50MB de RAM usada
3. **TTL (Time To Live):** Invalidar cache após N minutos (para hot-reload em dev)

**Quando usar:**

- ✅ **Assets estáticos:** HTML, CSS, JS, imagens pequenas
- ✅ **Arquivos acessados frequentemente:** index.html, logo.png
- ❌ **Arquivos grandes:** Vídeos, downloads (>10MB)
- ❌ **Arquivos dinâmicos:** Gerados por request (APIs)

  ```rust
  use std::collections::HashMap;

  pub struct ServerConfig {

      pub file_cache: RwLock<HashMap<PathBuf, Vec<u8>>>,
  }

  impl ServerConfig {
      pub fn new(custom_dir: Option<String>) -> Result<Self, String> {
          let dir_name = custom_dir
              .or_else(|| env::var("PUBLIC_DIR").ok())
              .unwrap_or_else(|| "public".to_string());

          let base_canonical = PathBuf::from(&dir_name)
              .canonicalize()
              .map_err(|e| format!("ERRO CRÍTICO: Caminho '{}' inacessível: {}", dir_name, e))?;

          Ok(Self {
              base_canonical,
              file_cache: RwLock::new(HashMap::new()),  // Cache vazio no início
          })
      }
  }
  ```

- [ ] **FUNÇÃO DE CACHE:** Criar helper para servir arquivos com cache:

  ```rust
  // Em shared/src/http/response.rs ou módulo novo
  use std::path::Path;
  use std::fs;

  const MAX_CACHEABLE_SIZE: u64 = 1_048_576; // 1MB

  pub fn serve_static_file(path: &Path, config: &ServerConfig) -> Result<Vec<u8>, String> {
      // Verificar tamanho antes de cachear
      let metadata = fs::metadata(path)
          .map_err(|_| "File not found".to_string())?;

      // Arquivos grandes: ler direto do disco (sem cache)
      if metadata.len() > MAX_CACHEABLE_SIZE {
          return fs::read(path)
              .map_err(|e| format!("Failed to read file: {}", e));
      }

      // Tentar cache hit (read lock - não bloqueia)
      {
          let cache = config.file_cache.read().unwrap();
          if let Some(cached) = cache.get(path) {
              return Ok(cached.clone());
          }
      }  // Read lock liberado aqui

      // Cache miss: ler do disco
      let data = fs::read(path)
          .map_err(|e| format!("Failed to read file: {}", e))?;

      // Inserir no cache (write lock - exclusivo)
      {
          let mut cache = config.file_cache.write().unwrap();

          // Verificar tamanho total do cache
          let current_size: usize = cache.values().map(|v| v.len()).sum();
          const MAX_CACHE_SIZE: usize = 52_428_800; // 50MB

          if current_size + data.len() < MAX_CACHE_SIZE {
              cache.insert(path.to_path_buf(), data.clone());
          }
          // Se cache cheio, não insere (LRU simples: mantém o que já está)
      }

      Ok(data)
  }
  ```
